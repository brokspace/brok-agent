# Changelog

All notable changes to this project are documented in this file.
The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project adheres to
[Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Fixed

- A file moved with `git mv` (or moved and committed) left its old path in the index: git's rename detection listed only the new name, so the old file was never reported as deleted. Change tracking now asks git for changes without rename detection (brokspace/brok-agent#22).

## [0.4.0] - 2026-11-24

### Added

- In a Meta Workspace, answers also draw on the member repositories (`search_members`, on by default): the agent asks the index for `scope: workspace` when the context lists members, and sources are cited as `member:path`. Needs brok 0.7 or newer and brok-sdk 0.3; without members or with an older brok nothing changes.

## [0.3.0] - 2026-11-23

### Added

- Token-aware context assembly (`context.max_input_tokens` and related
  settings): the prompt, history and retrieved chunks share a conservative
  token budget, overlapping chunks are dropped, chunks that do not fit are
  skipped instead of ending the selection, and the estimated tokens of each
  part are logged (counts only). Without it the character limits behave as
  before (brokspace/brok-agent#23).
- Event-driven change tracking: the agent watches the workspace with the
  operating system's file events (new `watch` setting: `auto`, `native` or
  `polling`) instead of asking git every 5 seconds. An idle workspace now
  starts no `git` process (it was about 18 in 30 seconds for a one-repository
  workspace), and an edit reaches the index in under a second. Events are
  debounced (`debounce_ms`), the queue is bounded, lost events trigger a full
  scan, `auto` also reconciles every `reconcile_interval_secs`, and the agent
  falls back to polling with a warning when the workspace cannot be watched.
  `watch: polling` keeps the previous behavior.
- Release builds attach Debian packages (`brok-agent_<version>_amd64.deb`,
  `arm64`) next to the standalone binaries.

### Changed

- crates.io publishing uses Trusted Publishing (OIDC) instead of a
  `CARGO_REGISTRY_TOKEN` secret, and starts on the release tag but waits for
  the GitHub release to be published.
- The Linux ARM64 binary is built with vendored OpenSSL and checked against
  its glibc floor (2.39), like x86_64.

### Fixed

- The Linux x86_64 binary ran only on the newest distributions: it was built
  on `ubuntu-latest` and needed its glibc (2.43) and libssl 3. It is now built
  on Ubuntu 20.04 with OpenSSL linked in, so it runs on glibc 2.31 and newer
  (Ubuntu 20.04+, Debian 11+). The release fails if it needs more.

### Added

- Cargo feature `vendored-openssl`: builds OpenSSL into the binary instead of
  using the system libssl.

## [0.2.1] - 2026-10-30

### Fixed

- The log names the workspace root repository `.` instead of `""`
  (`tracking git repositories repositories=["."]`).

## [0.2.0] - 2026-10-25

### Added

- Follow-up questions: `agent:ask` uses the conversation history sent by `brok chat` (last 12 turns,
  about 12 000 characters), and short follow-ups reuse the previous question for retrieval.
- Multi-repo workspaces: independent git repositories nested in the workspace (up to four levels deep)
  are tracked like submodules, also when the workspace root is not a repository; new clones are found
  within a minute.

### Changed

- The tracker follows each repository's `HEAD`: files changed by commits, pulls, checkouts and rebases
  are published as `file:changed`, so the index no longer goes stale after switching branches.
- Folders generated by brok (`.brokspace-managed` marker, e.g. exported skills) are ignored.
- `shard.json` no longer pins v0.1.0 release binaries; the v0.2.0 binaries are pinned after release.

## [0.1.0] - 2026-10-24

### Added

- Incremental change tracking through `git diff --name-only HEAD` and `git ls-files --others`, across the
  root repository and every initialized submodule; publishes `file:changed`.
- Optional pre-indexation LLM review of changed files selected by glob filters; publishes `review:result`.
- `agent:ask` handler: hybrid search through the core index service, Markdown context assembly within a
  character budget, secret redaction, and streamed answers (`agent:ask.chunk` → `agent:ask.done`).
- OpenAI-compatible chat completions client with a robust incremental SSE parser (Ollama, LM Studio,
  Anthropic, DeepSeek, OpenAI, vLLM, ...).
- Prompt validation and redaction of AWS, GitHub, Slack, `sk-` style keys, PEM private keys and
  `password = "..."` style assignments.
